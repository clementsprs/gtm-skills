# Brief template

Get this approved before building. It is short on purpose: one row per beat.

```md
# <Product> <feature> film: brief

Goal: <what the viewer should believe after 25 s>
Audience and channel: <for example "sales leaders, launch post + feature page">
Duration: <20-30 s>  Format: 16:9 first, then <1:1 / 4:5>
Brand surfaces read: <marketing page URL>, <app view>, <date>
Music: <licensed or generated track, source>

| # | Part | On-screen copy | What we show | Tool / API name | Claim source |
|---|------|----------------|--------------|-----------------|--------------|
| 0 | Hook | "<line A ink> / <line B grey>" then "<Product> makes it work." | Partner logos pop in | | |
| 1 | Beat | "01 <verb + outcome>" | Prompt: "<under 60 chars>" Card: <3-4 rows> Reply: "<one line>" | `<real_tool_name>` | |
| 2 | Beat | "02 ..." | ... | ... | |
| 3 | Beat | "03 ..." | ... (insight moment, highlighted) | ... | <source for the number> |
| 4 | Beat | "04 ..." | ... (payoff, for example a recap posted in team chat) | ... | |
| 5 | Finale | "<closing line, two lines>" | Backdrop to full frame, logotype, URL pill | | |

Notes:
- People and companies are fictional. UI numbers are illustrative unless a source is given.
- Tool names checked against: <API reference or tool list, date>.
```

## Writing good beat copy

- Captions: number + verb + outcome, 3-4 words ("Find relevant people", "Understand what works best").
- Prompts: how a real user would type it, under 60 characters, no feature jargon.
- Replies: one line, the result in plain words, ideally with one concrete number.
- Cards: 3-4 rows, one idea each. If a card needs a fifth row, the beat is doing two things: split or cut.
